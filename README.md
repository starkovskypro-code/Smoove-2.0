# Smoove 2.0

Исследовательский прототип плавной прокрутки для Windows 11 x64. Серия щелчков меняет одну общую траекторию положения и скорости, с разгоном и торможением. Код и проверки подготовлены; ощущение «как качественный тачпад» в сторонних приложениях ещё не подтверждено.

## Запуск готовой сборки

Откройте `out/prototype/Smoove.Probe.exe`. Эта локальная self-contained сборка содержит .NET; ничего устанавливать для её запуска не нужно. Переносить следует всю папку `out/prototype`, а не один `.exe`. Это прототип без установщика и автозапуска.

1. Поместите курсор в длинную страницу диагностического окна и вращайте колесо, оставляя курсор на месте.
2. Сравните «Отзывчивый» и «Тягучий». Можно менять расстояние, постоянные времени разгона и торможения; это параметры модели, не обещание точной длительности анимации.
3. «Эксперимент в Яндекс / Edge / Chrome / Firefox» теперь включён при запуске. Переключитесь в браузер и наведите курсор на длинную страницу. Галочка разрешает эксперимент; аппаратная и визуальная приёмка пользователя ещё необходима.
4. Для сравнения выключите «Сглаживать». В трее также есть пауза и выход. Закрытие окна оставляет прототип в трее; «Выход» завершает его.

Программы вне этого списка получают исходный ввод. Небольшое дрожание курсора до 8 пикселей не обрывает движение; смена области HWND, значительное перемещение, Ctrl/Shift/Alt, кнопки, смена активного окна, блокировка и события питания отменяют хвост. Сглаживается вертикальная ось разрешённого окна под курсором; неактивные окна также допускаются, если Windows направляет колесо под указатель. Elevated/неизвестные процессы пропускаются. Настройки пока действуют только до выхода. Строка состояния показывает, обработано ли последнее событие или по какой причине оно пропущено.

WinForms здесь используется как диагностический приёмник, который непосредственно отображает малые дельты без собственного сглаживания. Финальные настройки продукта по плану будут на WinUI 3 после проверки осуществимости.

## Разработка и проверки

Требуется .NET SDK 10; в текущей среде найден `C:\Users\Vladislav\.dotnet\dotnet.exe` версии 10.0.401. Скрипты сначала используют пользовательский `.dotnet`, затем `PATH`.

```powershell
.\scripts\Run-Prototype.ps1 -Build
.\scripts\Test-Prototype.ps1
```

Проверка настоящего Win32-пути в собственном receiver (предварительно закройте обычный прототип через «Выход»):

```powershell
.\scripts\Test-Prototype.ps1 -NativeInput
.\scripts\Test-Prototype.ps1 -NativeInput -YandexBrowser -Published
.\scripts\Test-Prototype.ps1 -TelegramChat
```

NativeInput сравнивает raw и smoothed перерисовку receiver. YandexBrowser открывает отдельный локальный профиль и измеряет scrollY/rAF. TelegramChat работает в текущей переписке, сравнивает raw и smoothed геометрию `HistoryWidget` и не отправляет сообщения. В обычной работе zero-extra wheel пользователя обрабатывается; собственные события не зацикливаются. Published проверяет self-contained exe. Эти проверки не заменяют субъективную приёмку реальной мыши.

Графики модели представлены CSV в `out/model-checks`; результат системной проверки — `out/native-input-check.txt`. Сборка готового прототипа:

```powershell
& "$env:USERPROFILE\.dotnet\dotnet.exe" publish src/Smoove.Probe/Smoove.Probe.csproj -c Release -r win-x64 --self-contained true -o out/prototype
```

## Состояние

- Реализованы общая модель, короткий hook на отдельном потоке, ограниченная очередь, worker, проверка контекста/прав, маркеры, отмена и diagnostic UI/tray.
- Автоматически проверены непрерывность состояния, сохранение расстояния и остатка, нерегулярные серии, разворот, отмена, оба профиля и полный controlled Win32-путь.
- Проверена доставка и движение страницы Яндекс Браузера и текущей переписки Telegram. Визуальная приёмка пользователя с его профилем/мышью, остальные приложения, горизонталь, производительность/энергия, WinUI, сохранение и релиз остаются следующими вехами.
