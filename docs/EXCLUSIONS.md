# Исключения — схема настроек 2

Две кнопки на странице «Исключения» расположены горизонтально с Spacing=12. Окно запущенных программ — отдельный WinUI Window, старт 800×600, изменяемый размер, центр относительно главного AppWindow. Поиск меняет список, но не размер окна. Выбор нескольких записей сохраняется при фильтрации.

Перечисление выполняется через Task.Run: только процессы текущего сеанса и владельца пользователя, с доступным полным путём к существующему EXE; папка Windows и сам Smoove исключаются. Дубликаты объединяются по пути без учёта регистра. Имя берётся из FileDescription с fallback на имя файла. Иконка извлекается Shell SHGetFileInfoW; HICON освобождается DestroyIcon, растровые данные передаются WinUI. Нет сетевой загрузки иконок. Недоступные и завершившиеся процессы пропускаются.

Выбор установленной программы — стандартный OpenFileDialog Windows, фильтр *.exe и существование файла, владелец — главное окно. Диалог работает на отдельном STA-потоке, без subclassing WinUI HWND и без блокировки input host. Отмена не меняет список.

Новые ApplicationExclusion содержат Path/Enabled/LegacyName. Полный путь нормализуется GetFullPath, сравнение OrdinalIgnoreCase; несколько версий одного EXE по разным путям независимы. Повторное добавление не создаёт карточку и не меняет выключенное состояние. Отключённая карточка хранится, но Matches возвращает false. Удаление удаляет запись. Карточки имеют EXE-иконку, имя, полный путь, доступный ToggleSwitch и кнопку Symbol.Delete.

При чтении старого Excluded (строка имён) записи мигрируют в LegacyName=true с подписью «Совместимое исключение • по имени файла». Они продолжают работать по имени и сохраняются в схеме 2. Настройки записываются через временный файл с резервной копией .bak и заменой. Невалидный/повреждённый файл или неизвестная более новая версия не перезаписываются; показывается ошибка. В таком случае изменения текущего сеанса не сохраняются до восстановления файла.

Политика передаётся в host снимком массива. Проверка пути процесса и совпадений выполняется в RefreshRoute вне low-level hook; callback читает только готовый допуск. Перечисление, Shell API и диалог не используются в callback и motion worker.

Проверено:

- Release self-contained публикация без ошибок/предупреждений.
- Модельные тесты миграции имён, JSON round-trip, нормализации/регистра, разделения v1/v2 путей и выключенной записи.
- WinUI: выбор двух программ, сохранение выбора после пустого результата поиска, неизменность окна при фильтрации, сохранение карточек в схеме 2, переключение Enabled=false и удаление. Тестовые записи удалены.
- Реальный файл схемы 1 с двумя именами после запуска перенесён в схему 2; исходные пользовательские настройки восстановлены.
- Системный диалог открытия наблюдался как дочернее окно владельца и отменён. Автовыбор EXE через этот диалог в сессии не выполнялся; добавление проверено через окно процессов.
- Повторная проверка пяти ползунков, навигации, сохранения и чтения после перезапуска прошла.

Иконки у удалённого/недоступного EXE могут отсутствовать. Для старой записи только по имени неизвестен точный EXE-путь, поэтому достоверную иконку конкретной версии получить нельзя. Системные процессы определяются по владельцу, сеансу и размещению в Windows; пользовательские фоновые утилиты могут присутствовать в списке.
