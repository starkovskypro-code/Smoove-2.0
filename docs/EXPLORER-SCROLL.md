# Проводник: отдельный путь для списка файлов

В папке `D:\Coding\Smoove 2.0\out\app` файловая область Windows 11 реализована DirectUIHWND под SHELLDLL_DefView. Сглаженные события колеса не гарантируют промежуточные смещения: Проводник может накапливать их и двигать целые строки.

Новый адаптер используется только для этой области процесса explorer.exe, при наличии ScrollPattern и вертикальной прокрутки. Он переводит общее движение Smoove в SetScrollPercent, сохраняя промежуточную позицию между импульсами. Высота строки и число строк системного колеса дают масштаб движения; итоговая геометрия зависит от режима просмотра Проводника. Постраничное колесо и отключённая системная прокрутка не включают адаптер.

Поиск automation provider, классов окна и размеров выполняется в RefreshRoute вне hook. Сам hook читает готовый маршрут; никакой UIA внутри callback нет. Worker отправляет промежуточные позиции; при недоступности провайдера обработка выключается и будущий ввод остаётся стандартным. UIA-вызовы межпроцессные и могут влиять на задержку, особенно при занятом Проводнике.

Ни дерево папок, ни панели предпросмотра, ни рабочий стол, ни остальные приложения на этот путь не переводятся. Эти поверхности требуют отдельной проверки. Исключения, пауза, модификаторы и смена контекста действуют по прежней политике.

Проверка: `scripts/Test-Prototype.ps1 -ExplorerFiles` использует первое открытое окно Проводника с файловой областью, временно поднимает его, прокручивает и восстанавливает начальную позицию. Файлы, выбор и режим просмотра не изменяются. Заново находится контрольная строка, поскольку Проводник виртуализирует элементы. CSV содержит только время и координату, без имени файла.

В реальной области out/app: исходный ввод — 3 изменения, максимальный шаг 192 px, расстояние 566 px; сглаженный путь — 24 измеренных изменения, максимальный шаг 86 px, расстояние 582 px. 12 входов по −30 полностью приняты; сумма −360 сохранена; 333 промежуточные команды Explorer, без отмен. UIA-измерение геометрии само медленнее выдачи команд: эти 24 изменения не являются FPS экрана. Результат подтверждает уменьшение шагов, а субъективную плавность нужно оценить пользователю.

Первый опубликованный релиз 0.5.0-beta.1 не заменяется этим изменением автоматически. Локальная out/app сборка обновляется для проверки; исправление находится в отдельной ветке/PR.

Финальная опубликованная локальная сборка также прошла сравнение: raw 3 изменения/192 px max step против smooth 24/80 px; 345 промежуточных команд. В обычном native receiver адаптер не включился (Explorer pixel moves=0), полный набор native/free-spin/настроек частоты прошёл. На начале каждого жеста размеры области и строк пересчитываются для изменения размера окна/режима просмотра. Список может виртуализировать элементы, но worker держит провайдера самого вида, а не отдельной строки.

## Сгруппированные папки и разные виды файлов

Поиск файла перенесён с Children на Descendants: в «Загрузках» файлы находятся внутри групп. Для масштаба выбирается видимый файл. Дочернее окно под курсором приводится к файловой области DirectUIHWND; переход между её дочерними окнами не отменяет движение. Поиск UIA остаётся вне hook; callback проверяет только Win32-иерархию окна.

Добавлена горизонтальная ось для режима «Список» и поддержка системного постраничного колеса. Нулевое системное число строк сохраняет исходное поведение. Ранее описанное ограничение только вертикальной осью больше не действует.

Проверка временно переключает семь видов и восстанавливает исходный вид и позицию. Каждый из видов 1, 2, 3, 4, 5, 6, 8 дал 24 из 24 промежуточных позиций ScrollPattern. Это проверка координат провайдера, не измерение FPS экрана. В исходном виде проверены реальные координаты файла: raw 3 изменения, максимальный шаг 93 px; smooth 13 изменений, максимальный шаг 27 px. Все 360 единиц ввода доставлены, без отмен. Произвольные папки, виртуальные пространства Shell и нагрузка сторонних расширений отдельно не проверены.

## Единая скорость при разных размерах значков

Устранено умножение расстояния колеса на высоту/ширину файла: крупные значки с многострочными именами давали многократно более быстрый скролл, чем таблица. Обычная строка колеса теперь равна 20 DIP, пересчитанным через GetDpiForWindow. Число строк Windows, общий множитель скорости и темповое ускорение Smoove сохраняются. В режиме системного постраничного колеса расстояние остаётся равным размеру области.

В открытой Корзине тест семи видов 1, 2, 3, 4, 5, 6, 8 подтвердил одинаковый один щелчок: 79,9 px при текущих DPI и настройках Windows. Во всех видах зарегистрированы 24/24 промежуточные позиции провайдера. В исходном виде измеренные скачки геометрии: raw max 84 px, smooth max 21 px; все 12 входов/360 единиц доставлены. Тест возвращает прежний вид папки и позицию. Измерения ScrollPattern не являются FPS экрана. Нормализация заменяет ранее описанный масштаб по размеру файла.
