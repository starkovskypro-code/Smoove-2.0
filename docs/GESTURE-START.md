# Начало жеста: устранение потерь и задержки

Пользователь сообщил непостоянные потери первых 1–3 щелчков и затянутый старт. Изменения сделаны в ветке codex/explorer-smooth-scroll; опубликованный ZIP beta.1 не обновлён.

Найденные причины в коде:

- Маршрут обновлялся WinForms UI timer, с тайм-аутом допуска 250 мс. Зависание UI или запрос automation provider могло заставить hook пропустить ввод и worker отменить уже принятый жест.
- Повторные Configure/SetExclusions с теми же значениями отменяли накопленное движение. Изменение обычных параметров также обрывало жест.
- TryWrite публиковал событие раньше координат начала жеста. Уже работающий worker мог прочитать новый ввод со старым якорем и отменить его.
- Модель стартовала с нулевой скорости, а выход округлялся до целой единицы колеса. Большие постоянные времени разгона и торможения усиливали задержку первого смещения.

Исправления:

- Выделен route thread, независимо от UI и hook. Он проверяет окно/указатель каждые 20 мс; токен/процесс для неизменного допустимого контекста обновляется раз в секунду. Частота не гарантируется планировщиком ОС.
- Стабильный маршрут не истекает только из-за паузы UI. Hook и worker всё ещё сверяют реальное окно/область, модификаторы, состояние политики и номер её ревизии; неизвестный/запрещённый контекст получает исходный ввод. После смены окна до подтверждения нового маршрута первый импульс может пройти исходным, а не быть преобразованным — не заявляется полная синхронность маршрутизации.
- Повторная неизменная политика идемпотентна. Настройка движения не сбрасывает позицию/скорость; пауза и изменение исключений отменяют хвост. Старый снимок маршрута после изменения политики не может разрешить ввод из другой ревизии.
- Якорь опубликован до события; worker проверяет координаты своего принятого события, не изменяемый якорь последующего ввода.
- Начало жеста получает небольшую скорость: 20% дельты / min(сумма постоянных времени, 200 мс). Позиция не прыгает, итоговая сумма сохраняется. Это осознанное изменение кривой старта, требующее субъективной приёмки; текущий разворот и продолжение серии не переинициализируют скорость.
- Модель учитывает время входного события, а не только момент извлечения из очереди. Задержанное событие не начинает разгон с нуля в момент dequeue.

Проверки:

- Модель: 20 стартов для каждого из трёх профилей, включая медленный 220/560 мс; первая целая дельта в пределах 16 мс модельного времени, без скачка позиции и без изменения общего расстояния. Существующие суммы, остатки, free-spin, ускорение и мягкие развороты прошли.
- Native integration: UI намеренно заблокирован на 800 мс, три wheel-входа подаются другим потоком; все −360 доставлены без отмены. Пять отдельных жестов после остановки и перемещения курсора внутри того же HWND сохраняют полный −120 каждый. Между вводом и завершением повторно задаются те же параметры и пустые исключения.
- Прогон после исправления якоря: PASS; max first-send 17,91 мс, max callback 1,157 мс; 96 000 единиц fast-spin сохранены, обычная пауза/маркеры/частота/отмена после значительного движения прошли. Это максимумы небольшой controlled выборки, не p99 и не аппаратная задержка.
- Повторный Explorer check остановился до серии: нет подходящей видимой контрольной строки. Это не PASS адаптера в новой версии. Дополнительно исправлена очистка topmost/курсора при такой остановке.

Не проверены любые нагрузки/драйверы и все приложения. Синхронные межпроцессные UIA вызовы Проводника всё ещё могут задержать его путь; подтверждённого решения зависшего стороннего процесса нет. Предел дрожания указателя 8 пикселей и остановка при смене HWND сохраняются намеренно. Реальную микрозадержку/пропуски после этой сборки должен оценить пользователь, прежде чем называть исправление полным.

Финальная self-contained сборка out/app прошла тот же native-тест: все 3 входа при 800 мс блокировки UI и 5 одиночных жестов сохранены; max first-send 17,93 мс, 96000 единиц fast-spin доставлены без отмен. Работа маршрутного потока добавляет пробуждения в простое; энергопотребление отдельно не измерено. HANDOFF.md содержит состояние до этой правки и оставлен без изменения как исторический handoff.
