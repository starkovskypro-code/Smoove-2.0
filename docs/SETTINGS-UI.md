# Нативные настройки Windows 11

Окно WinUI 3, Windows App SDK 1.8.260921001. Используются NavigationView, Slider, ToggleSwitch, ComboBox, Expander, InfoBar, системные типографические стили/ресурсы и Mica. Диагностический WinForms host работает на отдельном STA/message loop; перехват и motion-worker сохранены. Интерфейс управляет реальным движком, а не отдельной демонстрацией.

Прокрутка разделена на скорость, плавность/инерцию и точность. Под каждым параметром — пояснение эффекта и компромисса. Навигация адаптируется к ширине окна; содержимое страницы прокручивается вертикально. Ползунки имеют доступные названия и стандартный RangeValuePattern. В «Приложениях» — исключения и тема; технические счётчики вынесены в «Диагностику».

Настройки записываются локально с временным файлом и заменой; диапазоны проверяются при чтении. Светлая/тёмная темы осмотрены в рабочем окне. Автоматическая проверка пяти Slider, трёх разделов, записи ускорения 75 и чтения после перезапуска прошла. Значение возвращается к предыдущему после теста.

Порог tempo gain снижен: бонус начинает нарастать при обычном учащённом вращении раньше free-spin. Модельная проверка требует >1,45× при интервале 100 мс/ускорении 60% и 1× при медленном интервале 400 мс. Free-spin сохраняет рост основной скорости без потолка. Проверки существующей модели и новой чувствительности прошли.

Установлены WinUI template и инструменты через workflow winui-app. WinGet configuration завершена: Developer Mode и Visual Studio/managed desktop/Windows App SDK workloads. NuGet source закреплён на уровне репозитория, версии SDK зафиксированы. Установщик и пользовательский автозапуск добавлены в выпуске 1.0.0.

Готовая self-contained сборка: out/app/Smoove.Settings.exe. Ощущение ускорения на Logitech и визуальная совместимость всех приложений по-прежнему проверяются реальным пользователем. Высокий контраст и увеличенный системный текст предусмотрены штатными контролами, но отдельно в этой сессии не проверены.

## Меню трея

Контекстное меню пользовательского приложения заменено с WinForms ContextMenuStrip на штатный WinUI 3 MenuFlyout. Отдельное минимальное окно-владелец позволяет показывать меню у курсора, когда настройки скрыты; в переключателе окон оно не показывается. Закрытие flyout скрывает владельца. Тема соответствует настройкам, команды — настройки, плавная прокрутка и выход. Переключение использует тот же параметр страницы и сохраняется обычным хранилищем. Диагностический прототип сохраняет своё меню WinForms.

Исправлен crash при первом открытии меню: ShowAt вызывался до Loaded и создания XamlRoot служебного окна. Открытие теперь выполняется после Loaded либо сразу для уже загруженного элемента. Воспроизведён старый crash через штатное уведомление NotifyIcon WM_RBUTTONUP; после исправления первый и повторный вызовы показывают три пункта MenuFlyout, процесс отвечает. Проверка использовала callback трея и UI Automation; физический правый клик и все команды отдельно не проверены. Временное трассирование удалено.

## Автозапуск и рабочие столы

В настройках есть переключатель «Запускать при старте Windows». Он управляет записью Smoove в HKCU\Software\Microsoft\Windows\CurrentVersion\Run. При `--startup` создаётся host и скрытое окно настроек, без видимого окна. Установщик переносит запись только если она указывает на `Smoove.Settings.exe --startup`; при удалении снимает запись только для удаляемого пути. Windows может отключить запуск своей политикой, приложение это решение не обходит.

Служебное окно MenuFlyout и окно настроек проверяются через публичный IVirtualDesktopManager. Если окно находится на другом рабочем столе, создаётся новое на текущем. Для настроек переиспользуется та же MainPage с параметрами, выбранным разделом и состоянием; старое окно закрывается, вспомогательный picker закрывается при смене владельца. В меню у «Плавной прокрутки» добавлена штатная иконка TouchPointer, галочка состояния сохранена.

Проверено: TogglePattern включает/выключает запись с правильной командой, исходная регистрация восстановлена; --startup оставляет ноль видимых WinUI-окон, команда меню открывает настройки. На временном втором рабочем столе вызов callback трея показал меню; «Настройки» создала окно на текущем столе и закрыла исходный HWND. Временный стол удалён, исходный восстановлен. Иконка меню осмотрена на снимке out/tray-menu-updated.png. Реальный повторный вход в Windows и отключение через диспетчер задач не проверялись.

Вызов настроек на текущем рабочем столе теперь восстанавливает свёрнутое окно через OverlappedPresenter.Restore и активирует его штатным SetForegroundWindow. Команда меню ждёт Closed: активация до завершения popup могла вернуть фокус служебному владельцу. Постоянный topmost у окна настроек не включается. Регрессия tests/ui/Test-TrayActivation.ps1 -TrayCallback проверяет свёрнутое и перекрытое окно, IsIconic и фактический foreground HWND. Оба сценария прошли через уведомление NotifyIcon и UI Automation InvokePattern пункта меню. Путь с физическим/синтетическим попаданием по значку трея в этом прогоне не подтверждён: полноэкранная программа скрывала панель задач. Тест поддерживает отдельный режим реальных кликов и восстанавливает созданное тестовое окно и курсор.
