## Цепочка ввода и вывода

1. `SmoothScrollService.SetHook` (token 0x0600011e) вызывает SetWindowsHookEx с WH_MOUSE_LL = 14.
2. `HookCallback` (0x0600011f) принимает WM_MOUSEWHEEL = 0x20A и WM_MOUSEHWHEEL = 0x20E, извлекает signed 16-bit delta, окно под курсором и координаты. Собственные инъекции обходятся по dwExtraInfo. Учитываются включение, исключения, Pro-профили приложений, Ctrl+wheel, терминалы IDE.
3. `ApplySettingsToSmoother` (0x06000110) передаёт ровно четыре double: distancePerNotch, smoothnessMs, acceleration, inertia в SetScrollPhysics. Поле Easing не передаётся в физический движок.
4. `PushScrollEvent` (RVA 0x2CE0) ставит запись в кольцевую очередь под mutex: delta, QPC timestamp, HWND, координаты, Ctrl/Shift, горизонтальная ось. Индексы modulo 256; при заполнении старейшая запись вытесняется.
5. `StartSmoothScroll` (RVA 0x2ED0) создаёт поток через _beginthreadex. Worker RVA 0x2010/0x212B забирает очередь и обновляет состояния. Входной обработчик расчёта RVA 0x18B0; анимационный шаг RVA 0x1BC0.
6. Канал подбирается по HWND и горизонтальному признаку (RVA 0x1730). Таблица содержит шесть слотов. Несколько щелчков складываются в оставшееся расстояние одного канала, не создают независимые анимации.
7. Выходной участок RVA 0x1E2A–0x1F33 выдаёт WM_MOUSEWHEEL/WM_MOUSEHWHEEL через PostMessageW для обычного пути; для распознанных классов окон — SendInput. При ошибке PostMessage канал переключается на SendInput. Свой dwExtraInfo = 0xBEEF1234 препятствует повторному сглаживанию.

## Физика: восстановленные выражения

Обозначения ниже назначены аналитиком по использованию полей, не взяты из исходника. Формулы выведены из машинных инструкций и констант, а не из описаний ползунков.

**Ускорение от ввода** (RVA 0x1913–0x1B88):

```text
n = wheelDelta / 120
dtMs = max(1, интервал между событиями)
если интервал > 300 мс: rate = 0
rate += (min(100, abs(n)/(dtMs/1000)) - rate) * (1 - exp(-dtMs/80))
gain = 1 + 3 * acceleration * tanh(max(rate - 8, 0)/30)
remaining += wheelDelta * distancePerNotch * gain
remaining ограничен ±36000 wheel units
```

Оценка rate общая для событий движка, а не отдельная независимая оценка каждой оси. Значение сохраняется также в канале. Это gain расстояния при быстром колесе, не масштаб времени.

**Сглаживание и инерция** (RVA 0x1BC0–0x1DEC):

```text
tauMs = smoothnessMs * (1 + inertia * tanh(max(channelRate - 8, 0)/25))
desiredVelocity = remaining / smoothnessMs
на одной ветке скорость сразу принимает desiredVelocity;
на другой: velocity *= exp(-frameDtMs/tauMs)
step = velocity * frameDtMs
```

Когда desiredVelocity имеет тот же знак и большую абсолютную величину, чем прежняя скорость, он принимается сразу; при затухании применяется экспонента. После 120 мс без нового события канал переходит в хвост. При ненулевом усилении инерции и `abs(velocity)*tauMs > abs(remaining)` remaining увеличивается до `sign(velocity)*min(abs(velocity)*tauMs,36000)`. Поэтому inertia способна увеличить итоговое расстояние, а не только растянуть заранее фиксированный путь.

Шаг ограничивается остатком, при малом остатке (<6 wheel units) хвост добирается. Дробная часть сохраняется в канале; целый выход ограничен ±1200 за выдачу, избыток возвращается в остаток. Не следует смешивать wheel units с пикселями: приложение-получатель само интерпретирует wheel delta.

**Разворот** (RVA 0x1A81–0x1AC8): при противоположном знаке delta и оставшегося расстояния обнуляются remaining, дробный остаток и velocity, сбрасывается rate, затем добавляется новый ввод. Накопленный старый путь отменяется. Непрерывность прежней скорости не сохраняется; специального режима «первый обратный щелчок — тормоз» в найденной ветке нет.

**Темп:** текущий UI содержит distance 0,5–12; smoothness 20–200 мс; acceleration/inertia 0–2. AnimationSpeed/Steps/StepDelay/ScrollMultiplier — старые поля. ShouldSerialize… возвращают false, MigrateLegacyFields переносит `AnimationSpeed * ScrollMultiplier * 2` в DistancePerNotch, `Steps * StepDelay` — в SmoothnessMs, затем обнуляет старые значения. Отдельного общего dt-множителя в найденной цепочке нет. Историческое имя AnimationSpeed обозначало величину, участвующую в расстоянии, и не доказывает временной темп.

## Тайминг и расход ресурсов

RVA 0x1080 определяет монитор под курсором и его refresh rate. Период = clamp(1000/(2*refreshHz), 2, 20) мс; fallback 8,333 мс. Например, 60 Гц → 120 расчётов/с, 144 Гц → 288, максимум 500. Данные монитора обновляются примерно раз в 2 с.

Worker имеет THREAD_PRIORITY_HIGHEST (значение 2), измеряет время QPC и спит до следующего срока через C++ _Thrd_sleep. C# запрашивает timeBeginPeriod(1), снимая запрос при остановке. Периодический цикл продолжает работать без активного движения; это не доказательство высокого фактического CPU, но отличие от событийного idle-wait Smoove. При задержке кадра >250 мс состояния сбрасываются; frame dt ограничивается относительно периода.

## Почему маленький установщик

Подтверждено: маленький прикладной код, нативная физика 26 КБ, HTML встроен в основной EXE, Framework 4.7.2 используется извне, Edge/WebView2 browser runtime не вложен. При отсутствии WebView2 CIL предусматривает сообщение «Scrolling itself keeps working without it» и предложение открыть страницу загрузки. Нативная DLL также зависит от внешнего VC runtime. Локальная установка/наличие этих зависимостей не проверялись.

Inno использует LZMA, но основной выигрыш относительно Smoove — состав поставки. Наш `scripts/Build-Installer.ps1` публикует self-contained .NET 10, без trimming/ReadyToRun; Settings.csproj включает self-contained Windows App SDK. Наш Inno уже использует LZMA2/max и solid compression. Существующие локальные артефакты: Setup 1.0.0 = 71 754 692 байта, ZIP 1.0.1 = 143 382 675 байт. Это разные версии/форматы; не сравнение одинаковых релизов. Текущий out/app = 369 495 508 байт, это рабочая папка, не нормализованный release payload.

Уменьшение нашего пакета в первую очередь требует решения о framework-dependent поставке и внешнем Windows App SDK. Это перенесёт часть веса в требования к компьютеру или установку зависимостей. Перенос физики в C++ сам по себе runtime/UI из поставки не удалит.

| Щелчки складываются в remaining | Один Position/Velocity/Target на ось | Оба объединяют ввод | Основная архитектура уже сопоставима |
